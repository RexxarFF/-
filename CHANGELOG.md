# История выпусков

Актуальные правила — в README.md и UPDATE_0.4.0.txt.

## Обновление 0.4.0: интерфейс ученика и устойчивость

Короткая справка по темам, вступление по приглашению, тексты на «ты», личный прогресс
выполнения. Исправлены длинные списки, эмодзи, пустой срок черновика и редактирование
статуса «Ничего не задано». Ускорен поиск учебных дней; запросы разных пользователей
обрабатываются независимо. Кэш ограничен и повторно проверяет роли. Резервное копирование
работает без токена, неподдерживаемая схема отклоняется до миграции.

## Обновление 0.2.4: общее приглашение и своё меню

Владелец или участник с правом **Участники** пишет в привязанной группе **пригласить**
или `/invite`. Бот публикует одно общее сообщение с кнопкой **Вступить в класс**.
Одноклассник нажимает её и запускает бота в личке. Бот проверяет его текущее участие
в этой группе через Telegram и добавляет в нужный класс. Предварительный выбор каждого
человека больше не нужен. Из лички это доступно через **Управление → Пригласить класс**.

Приглашение действует 7 дней. Новая ссылка закрывает прежнюю; можно закрыть её вручную.
Перепривязка группы и исключение участника закрывают старые приглашения. Если создатель
приглашения теряет право управления участниками, его ссылка перестаёт работать.
Повторный вход уже добавленного ученика сохраняет его роли и личные записи.

Назначьте бота администратором группы: это нужно для надёжной проверки участия и
получения команд словами. Бот публикует общее сообщение, а не отправляет приглашение
каждому в личку. Участник сам открывает бота. Для удаления старой кнопки в группе можно
удалить сообщение; после закрытия ссылка в нём уже не действует.

Кнопки групповых `/menu` и `/stats` доступны только автору запроса. Другому участнику
бот предлагает открыть своё меню. Автор сохраняется в базе и после перезапуска.
Старое меню без данных об авторе нужно вызвать заново. Из групповой статистики убрана
кнопка **ДЗ в личку**; команды домашки и кнопка общего ДЗ в меню остаются доступными.
Общее приглашение в класс и адресное согласие на парный огонёк имеют свои правила доступа.

| Можно написать | Действие |
| --- | --- |
| меню | Свои кнопки |
| дз / домашка | Общее ДЗ на завтра |
| дз сегодня | Общее ДЗ на сегодня |
| мои записи / моё дз | Личные записи |
| расп / расписание / уроки | Расписание недели |
| расп завтра | Расписание на завтра |
| стата / статистика | Статистика сообщений |
| огоньки / огонёк | Парные огоньки |
| пригласить / пригласить класс | Приглашение в класс |
| помощь / команды | Справка |
| отмена / назад | Выйти из ввода в меню |

Английские команды со слешем сохранены. При наборе ДЗ, имени или объявления слова
считаются вводимым текстом; **меню**, **отмена**, **назад** выходят из ввода.
Для слов в группе бот должен получать обычные сообщения. ДЗ и расписание приходят
в личку, статистика и огоньки показываются в группе.

Обновление: сохраните `.env` и `data`, замените исходники и сделайте новый деплой.
Две новые таблицы создаются автоматически в существующей SQLite; создавать базу заново
не нужно. Проверка миграции сохраняет классы, домашку, роли и черновики.

## Обновление 0.2.3: статистика и интерактив в группе

Ответы на запросы из привязанной группы теперь приходят по разделам:

| Запрос | Куда приходит ответ |
| --- | --- |
| `/stats`, «моя статистика» | В группу: сообщения, личная серия и активность класса |
| `/pairs`, `/interactive`, «огоньки» | В группу: парные огоньки и управление приглашениями |
| `/hw`, `/my`, `/schedule`, запросы о домашке и расписании | В личку отправителю запроса |

Кнопки группового меню работают по тем же правилам. Карточки интерактива обновляются
в группе; они не меняют личную панель и незаконченный черновик ДЗ. В теме группы
новые ответы приходят в ту же тему. Групповые приглашения в парные огоньки
публикуются в группе; принять приглашение может только адресат. Остальные действия
с личной карточкой огоньков доступны владельцу этой карточки.

Команды, отправленные в личке, по-прежнему открывают личный интерфейс.
При обновлении сохраните `.env` и `data`, замените исходники и выполните новый деплой.

## Исправление 0.2.2: ответ из группы не появлялся в личке

В версиях 0.2.0–0.2.1 запрос из группы редактировал старое сообщение в личке.
Это могло выглядеть как отсутствие ответа. Теперь команда или кнопка в группе
отправляет **новое сообщение в личку**. Только после успешной отправки бот пытается
удалить прежнюю панель навигации. Если Telegram не разрешает её удалить, новая
панель всё равно работает. Дальнейшие кнопки в личке редактируют новую панель.

- На текстовый запрос в группе бот подтверждает успешную доставку. Домашка остаётся в личке.
- `/my` теперь работает и в группе: личные записи получает только отправитель запроса.
- Недоступная личка, отсутствие доступа к классу, ошибка форматирования, сетевой сбой
  и ограничение частоты отправки показываются разными сообщениями.
- Добавлены интервалы отправки для одного чата и повтор короткого ограничения Telegram.
  Долгое ограничение показывается пользователю; сетевые ошибки автоматически не
  повторяются, чтобы не продублировать уже принятую Telegram отправку.
- В группах с темами подтверждения и меню приходят в ту тему, где задан вопрос.
- Лог `Group private reply sent` появляется после подтверждённой отправки в личку;
  `Group private reply failed` содержит категорию ошибки без текста домашки.

Обновление исходников не меняет классы, привязки, расписание и сохранённые задания.

## Исправление 0.2.1: бот молчит в группе

- На команды и явные запросы в непривязанной группе бот отвечает инструкцией по привязке.
- Если сообщение отправлено от имени группы или канала, бот просит переключиться на
  личный аккаунт. Неизвестному отправителю не выдаётся доступ к данным класса.
- Команда `/groupcheck@username_бота` проверяет привязку, ваш доступ к классу,
  статус администратора у бота и Privacy Mode. Подставьте username своего бота.
- Обращения `@username_бота, что задано на завтра?` теперь тоже обрабатываются.
- В журнале появляются строки `Group message received` с ID группы, видом сообщения
  и признаком отправки от имени чата. Тексты сообщений в журнал не записываются.

Сохраните прежние `.env` и `data`, замените исходники и сделайте новый деплой.
Новая таблица или сброс базы для этого исправления не нужны. Шаги — в `GROUP_DEBUG.txt`.

## Обновление 0.2.0

- Кнопки меняют одно сообщение в личке, включая возврат назад. После перезапуска
  бот продолжает использовать это сообщение. Если его удалить, бот создаст новое.
- Длинные списки открываются страницами. Фото и файлы задания приходят отдельными
  временными сообщениями бота; при следующем действии бот пытается убрать эти превью.
  Сообщения, которые вы отправили сами, остаются в чате.
- День записи и срок выполнения выбираются в календаре с переходами по месяцам.
  Сегодня, вчера и завтра вычисляются по часовому поясу класса.
- Расписание открывается на всю неделю; доступны соседние недели и подробности дня.
- Объявление после подтверждения сразу отправляется в привязанную группу с именными
  упоминаниями участников класса. Личные уведомления отправляются отдельно от меню.
- Фразы «что задано на завтра» и «расписание на завтра» в группе присылают ответ в личку.
- Старые задания очищаются автоматически через 14 дней после создания записи,
  если срок выполнения уже прошёл. Задания на сегодня и будущие даты сохраняются.

Для обновления сохраните прежние `.env` и каталог `data`, замените исходники и
выполните новый деплой. Таблицы существующей базы обновляются автоматически.
Пошаговая инструкция — в `UPDATE_0.2.0.txt`.
